---
name: openspec-runner-coordinate
description: Coordinate explicitly selected single-harness OpenSpec task batches with openspec-runner, inspect sessions and reports, and integrate reviewed results.
---

Run `openspec-runner status <change> --json` and show ready tasks with their assignments. Confirm one batch harness from the preview; use `--agent claude` or `--agent codex` when selecting it explicitly. Before previewing, verify every selected task is ready. A dependency selected in the same batch is not satisfied until it has been integrated; if any selected task is blocked, show the unmet dependencies and required sequence instead of running `launch`. Preview an entirely ready batch using `openspec-runner launch <change> --tasks 2.1,2.2 --agent <harness> --dry-run --json`, then run the same command without --dry-run only after user approval. Do not start a continuous scheduler. Claude previews show unsupported calling-session inheritance and its configured permission policy; supply `--default-model` or explicit task models.

Inside Herdr, the runner creates one workspace per task without moving focus. Inside fmfsaisai/orca, `terminal: orca` (or auto-detection through `ORCA=1`, `ORCA_SESSION`, and `TMUX`) creates a dedicated tmux window per supervised worker. Use `worktrees: orca` to select Orca's worktree helper too; worktree selection is independent of terminal selection. Coordinate from the existing Orca lead session; use the runner for dispatch and cleanup of its tasks, rather than Orca's interactive worker panes or `orca-worktree remove/clean`. Outside either environment, present the returned supervised worker commands for separate user terminals. Do not substitute an unrequested background launcher. Use `attach` for existing sessions. A dry-run that fails because restricted subprocess execution suppresses command output may be repeated with the necessary execution permission because it creates no resources; never treat that retry as approval for a real launch. A timeout or blocked/ambiguous real launch is not permission to resubmit or start another session. Inspect saved pane identifiers; after restart, use the exact saved Codex or Claude resume recipe only when identity was confirmed. A worker's normalized structured report and real exit receipt, not terminal activity indicators or a Claude result event, establish an eligible result.

Review the report, verification evidence, commit, and worktree before integrating the user's selected results with `integrate <change> --tasks ...`. Integration changes checkboxes only in the dedicated integration worktree. Stop at conflicts or failed checks; inspect and resolve before `integrate --continue`, or explicitly abort with `integrate --abort`. Dependents remain blocked until integration completes.

A worker reporting blocked or failed has stopped implementation. New workers run a supervised Codex or Claude CLI process and exit after their final turn; report acceptance alone does not prove process exit. Inspect the saved worker exit receipt, immutable harness/session identity, normalized terminal evidence, and log. Request a new attempt with `retry` when the user wants further implementation. Do not resume finished workers in removed worktrees.

After successful integration, inspect the cleanup summary: automatic cleanup closes verified owned terminals and removes eligible task worktrees; completion of all planned tasks also sweeps obsolete attempts. Keep branches and the integration worktree. For every `confirmation-required` item, show its exact path, reasons, changed files, and terminal activity, then ask the user whether to delete it/close the reviewed terminal. Warn that uncommitted and ignored files in the directory will be discarded. No response means keep. Apply only approved candidates with `cleanup <change> --tasks ... --attempt ID --confirm TOKEN --json`, or `cleanup <change> --all --attempt ID --confirm TOKEN --json` for final-sweep candidates. Fresh changes require a fresh review. Never fabricate consent or use tokens without user approval.

For skipped resources, resolve ownership or worker-exit uncertainty before retrying. Close manually opened terminals only when the user authorizes it; confirm their closure before worktree deletion. Retry leftovers with `cleanup --all --dry-run --json` and then the approved cleanup operation. `cleanup: manual` keeps terminals/worktrees until explicit cleanup. Cleanup errors do not invalidate successful integration. Final integration-branch delivery and OpenSpec archival require explicit user action.
